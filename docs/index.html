ULAB Student Companion

A Chrome side-panel extension for ULAB students on the student URMS portal (urms-online.ulab.edu.bd) — a light visual reskin plus a self-advising checker, built the same way as its sibling project, ULAB Faculty Companion.

🔒 Privacy Policy 🏗️ Architecture 🧩 Features 🗺️ Roadmap / TODOs
This extension is under active development. Only the login and home pages of the student portal have been mapped so far (reference-html/login.html, reference-html/dashboard.html) — schedule, billing, preregistration, results and profile pages are not yet reskinned or scraped, and a further UI-revamp reference is expected. See Roadmap below.

🏗️ Architecture

Same shape as ULAB Faculty Companion: a plain MV3 Chrome extension, no build step, everything running client-side against the student's own already-logged-in urms-online.ulab.edu.bd session — no third-party server involved anywhere.

Feature registration

Each side-panel feature registers itself onto window.ULAB_FEATURES with { id, icon, title, subtitle, mount(container) } — sidebar/sidebar.js is a generic router over that array, copied verbatim from the faculty project since the pattern is entirely project-agnostic.

The dashboard shell

features/shared/ulab-dashboard-shell.js is intentionally much smaller than its faculty-companion counterpart. That version reskins a modern Bootstrap/ASP.NET site with a full persistent sidebar replacing the stock nav. This student portal is 2005-era table-layout HTML with no such structure — and a UI-revamp reference is expected separately — so for now the shell only owns what's safe regardless of that future design: the cloak/uncloak anti-flash trick, theme persistence, a small "Modern UI" toggle, and a central scrape of the semester/student/adviser header line every dashboard-style page shares.

Defensive page matching

Unlike the faculty portal, login and the logged-in Home page can both resolve at the same URL on this site depending on session state. Both content scripts therefore check for the actual DOM they need (a login form's studentID/password inputs, or #menubar) before doing anything, and cleanly no-op otherwise — matching the approach the handoff notes call for ("matched defensively... check for presence of the login form / absence of #menubar").

🧩 Features

🔐 Modern login overlay Live

Draws a modern split-screen layout over the stock table-based login form, without touching the real <form method="POST" action="/index.php"> — a mirrored input just relays keystrokes into the real studentID/password fields and clicks the real submit button.

🏠 Modern home reskin Live

Light CSS polish over the Home page's dashboard link table, plus a small summary card (semester, your name/ID, adviser name & email) rendered from data scraped out of the page's own header sentence — the original sentence stays in the DOM, just visually superseded.

🎓 My Advising Check Live (manual input)

The self-serve, first-person version of the faculty companion's Student Advising feature. Same rule engine — prerequisite violations, labs registered without their theory course, retakes of previously-failed courses, and per-category degree-progress credit gaps — reusing the exact same catalogues/*.js course data (verified byte-identical to the faculty project's copy).

Manual input for now: there's no known page yet that exposes a student's own completed-course history or in-progress registration in scrapeable form (only login + home have been handed off) — you currently paste in your grades and this semester's course list by hand. See Roadmap.
